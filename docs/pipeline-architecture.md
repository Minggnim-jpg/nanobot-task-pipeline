**创建时间**: 2026-03-05 15:08  
**状态**: 开发中

---

## 📋 核心需求

| 维度 | 要求 |
|------|------|
| **运行模式** | 搭建期 (每阶段确认) / 正式期 (全自动) |
| **子代理限制** | 同时活跃 ≤ 5 个 |
| **超时时间** | 所有阶段统一 1 小时 |
| **心跳轮询** | 5 分钟间隔 |
| **项目确认** | 每次都确认 (明确则用，未明确则问) |
| **任务 ID** | `task-{YYYYMMDDHHmmss}-{6 位随机码}` |
| **原始任务** | 必须记录用户原文，汇报时说明 |
| **通知策略** | 搭建期每阶段通知，正式期只通知 PR 完成/失败 |
| **错误处理** | 失败直接报告，不重试 |

---

## 🏗️ 架构设计

```
[CHANNEL_NAME] → 任务初始化 → HEARTBEAT 轮询 (5 分钟) → 子代理执行 → 汇报
         │                                      │
         ├─→ 记录 original-task.md              ├─→ todo (需求分析)
         ├─→ 确认项目                           ├─→ coding (开发)
         ├─→ 生成任务 ID                        ├─→ review (审查)
         └─→ 创建 status.md                     └─→ PR (提交)
```

## 🔄 心跳轮询逻辑

```
1. 读取 active-agents.md → 获取活跃子代理数量
2. 如数量 ≥ 5 → 跳过本次轮询
3. 扫描 /tasks/*/status.md
   ├─→ 检查超时 → 状态=abandoned
   ├─→ 状态=failed/complete/abandoned → 跳过
   └─→ 状态=pending/waiting_confirm → 检查阶段
4. 对于每个待执行任务：
   ├─→ [搭建期] waiting_confirm → 等待用户"OK"，跳过
   └─→ [正式期] pending → 活跃子代理<5 → 启动子代理
5. 更新 active-agents.md
```

## 🗂️ MEMORY.md 规则

```markdown
## 任务流水线规则

### 运行模式
- 搭建期：每阶段完成后等待用户"OK"确认
- 正式期：自动流转，只通知 PR 完成/失败

### 子代理限制
- 同时活跃子代理 ≤ 5 个
- 超限等待下次心跳轮询

### 超时处理
- 所有阶段统一超时时间：1 小时
- 超时自动抛弃任务，状态=abandoned

### 通知策略
- 搭建期：每阶段通知，含原始任务摘要
- 正式期：只通知 PR 完成/失败，含原始任务摘要
- 任何失败：立即通知，含原始任务摘要

### 项目确认
- 每次都确认项目
- 用户明确指定则使用
- 未明确则询问

### 确认机制
- 用户回复"OK"或表达可以的意思即确认

### 任务 ID 规则
- 格式：task-{YYYYMMDDHHmmss}-{6 位随机码}
- 示例：task-20260305150600-a1b2c3

### 心跳轮询
- 间隔：5 分钟
- 检查：超时、待执行阶段、子代理数量
```
